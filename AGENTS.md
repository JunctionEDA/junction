# Instructions for agents

Junction is a fork of KiCad with real-time collaboration, a browser editor and an MCP server. It is growing into
a multi-domain engineering app (see [docs/ROADMAP.md](docs/ROADMAP.md)). [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
maps the repository.

This repository is not KiCad. Junction's issues and pull requests belong on GitHub, not on KiCad's GitLab.

## Where code goes

- `server/web/`: the browser app. `shared/` and `platform/` are common to every domain. `domains/<id>/` is one
  kind of design work (`domains/pcb` is the electronics editor). Read `server/web/README.md` before adding files.
- `server/src/`: the Rust server (collaboration, storage, auth, MCP).
- The C++ desktop app is the KiCad tree at the root (`common/`, `eeschema/`, `pcbnew/`, …). Do not move or rename
  its directories. Every week `upstream-sync` merges KiCad master into it, and moved paths would conflict.
- To delete a file KiCad still has upstream, also list it in `tools/upstream-sync/ours.txt`. Otherwise the next
  merge brings it back.

## Generated files

- `server/web/domains/pcb/generated/*` comes from `server/scripts/gen_*.py`. Regenerate it; don't edit it.
- `server/static/*.js` and `server/static/dist/*` are build outputs of `npm run build`. They are committed, so
  rebuild them when you change `server/web`.
- `*_base.cpp` / `*_base.h` are generated by wxFormBuilder from the `.fbp` files. Don't edit them by hand.

## Checks before you finish

The same checks run in CI (`.github/workflows/ci.yml`):

    cd server && npm ci && npm run check && npm run build && node scripts/ci-web-tests.mjs
    cd server && cargo test --locked && cargo clippy --locked --all-targets
    cd server/harness && python3 -m unittest discover -s tests

After `npm run build`, `git status server/static` should show only the bundles your change was meant to touch.

C++ changes follow KiCad's code style (`_clang-format`, https://dev-docs.kicad.org/en/rules-guidelines/code-style/).
